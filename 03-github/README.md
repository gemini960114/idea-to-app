# 功能改進與 GitHub：測試、改進、留下修改紀錄

約 100 分鐘。認識 git 和 GitHub，替作品增加實用功能、認真測試，並讓每一次修改都留下紀錄；最後把作品發布成一個網址，分享給同學。

**重點：AI 說「做好了」，不代表沒有 bug。** 自己測試、請另一個 AI 審查，確認沒問題再存成一個版本。

> **課前準備**：完成 [接手自己的專案](../02-my-project/README.md)，作品已經推上 GitHub。

---

## Step 1：把作品找回來

電腦已經還原，先把上次的作品拿回來：

1. 在「文件」裡新建一個空資料夾 `my-app`，用 **Open Folder** 打開。（repo 名稱忘了的話，看之前的 e-Peer 紀錄，或登入 GitHub 網頁查看。）
2. 照 [登入 GitHub](../01-install/README.md#登入-github每次上課都要做) 的步驟登入。
3. 對 AI 說：

   **Prompt 1：下載自己的作品**

   ```text
   請把我 GitHub 上的〔你的 repo 名稱〕用 git clone 下載到這個資料夾裡（直接放在目前資料夾，不要多一層），
   然後安裝需要的套件，啟動開發伺服器，告訴我網址。
   ```

4. 作品有用到 Gemini API 的話，照 [金鑰步驟](../02-my-project/README.md#作品有用到-gemini-api-的話) 重新放入金鑰。

## Step 2：認識 git 和 GitHub

上次最後，你已經照做了一次「存到 GitHub」。現在來看看它到底做了什麼：

| 名詞 | 意思 |
| :--- | :--- |
| **git** | 記錄版本的工具，在你的電腦上運作 |
| **GitHub** | 放 git 版本紀錄的網站，像作品的雲端備份 |
| **repo**（儲存庫） | 一個作品的資料夾，連同所有歷史版本 |
| **commit** | 存一個版本，並寫一句說明「這次改了什麼」 |
| **push** | 把電腦上的版本推到 GitHub |

**先記住一句話：登入和 GitHub 網站上的事用 `gh`，檔案的版本（commit、push）用 `git`。**

**Prompt 2：看看版本紀錄**

```text
請列出這個專案所有的 commit，用簡單的話說明每一個版本改了什麼。
```

也可以到 GitHub 網頁打開你的 repo，點 **commits**，看到同樣的紀錄。從 AI Studio 搬過來的作品，可能還有 AI Studio 自動留下的版本。

## Step 3：自己測試

你最清楚自己想做的是什麼。先寫下 **3～5 個檢查項目**，再實際操作一輪，逐項確認。例如：

| 作品類型 | 可以檢查的項目 |
| :--- | :--- |
| 遊戲 | 規則正確嗎？分數和計時對嗎？遊戲結束後能重新開始嗎？快速連點會不會出錯？ |
| 工具（番茄鐘、讀書小幫手） | 每個按鈕都有作用嗎？時間或數字算得對嗎？輸入空白或奇怪的內容會怎樣？ |
| 有 AI 功能的 App | AI 產生的內容**正確嗎**？例如單字的解釋、題目的答案，要自己查證。沒有網路或金鑰時，畫面會怎麼顯示？ |

記下你發現的問題，等一下一起修。

## Step 4：請另一個 AI 審查

同一個 AI 很難發現自己的錯，所以請**另一個 AI** 來審查：在對話面板開一個**新對話**，順便換一個模型，再貼上 Prompt 3。新對話不知道前面的過程，就像請一位沒看過的人重新檢查。

**Prompt 3：交叉審查**

```text
請審查這個資料夾裡的 App 有沒有 bug 或不合理的地方。
要實際執行或操作驗證，不要只看程式碼；先不要修改檔案。
最後用表格列出你發現的問題、嚴重程度和修改建議。
```

審查 AI 說「有問題」的地方，**先自己在 App 裡試試看是不是真的**。審查 AI 也可能判斷錯，最後決定的人是你。

## Step 5：一次改一件事，每一步都存起來

回到原本的對話，先修正 Step 3、Step 4 確認過的問題，再加上實用的功能，例如最高分紀錄、說明頁、設定頁、深色模式。

每一件事都照這個循環：

```text
改一件事 → 自己確認 → commit 並推上 GitHub
```

**Prompt 4：修改一件事**

```text
〔描述一個確認過的問題，或一個想加的功能，例如：遊戲結束後按「重新開始」，分數沒有歸零〕
請先告訴我打算怎麼改；我同意後再修改，改好後告訴我怎麼確認。
```

自己確認沒問題後：

**Prompt 5：存成一個版本**

```text
把剛才的修改 commit（說明寫清楚改了什麼），並推上 GitHub。
```

> [!TIP]
> commit 的說明要寫清楚，例如「修正：重新開始時分數沒有歸零」，不要只寫「更新」。之後做成果簡報時，這些說明就是你的修改紀錄。

## Step 6：改壞了怎麼辦？

git 記得每一個版本，改壞了可以回到之前的版本。試一次看看：

**Prompt 6：還原**

```text
我剛才的修改沒有 commit，請把程式還原到最後一次 commit 的狀態。
```

已經 commit 的版本，也可以請 AI「把某一個 commit 的修改撤回」，並說明會發生什麼事，確認後再做。

## Step 7（時間夠再做）：發布到網路上（沒有用到 Gemini API 的作品）

> [!WARNING]
> **有用到 Gemini API 的作品不要發布。** 發布後網頁的程式任何人都看得到，金鑰會被別人拿去使用。這類作品在自己的電腦上展示就好。

**Prompt 7：發布到 GitHub Pages**

```text
請把這個作品發布到 GitHub Pages：repo 要是 public 才能發布（是 private 的話先改成 public），
用 gh-pages 套件把 build 的結果發布到 gh-pages 分支（不要建立 GitHub Actions 的 workflow 檔），
記得設定 vite 的 base，完成後給我網址。
```

「base」是告訴網頁它放在哪個網址底下；沒設定好，打開會是一片空白。

**怎麼確認成功**：用瀏覽器打開 AI 給的網址（類似 `https://你的帳號.github.io/my-app/`），作品能正常操作就完成了。畫面空白或打不開時，等 1～2 分鐘再重新整理；還是不行，把情況告訴 AI。

把網址傳給同學，手機也能打開。

## 下課前

1. 截一張作品畫面：按 `Win + Shift + S` 框選畫面，點右下角跳出的通知，在剪取工具按「儲存」，存進作品資料夾裡的 `screenshots` 資料夾。
2. 把最後的修改和截圖一起存起來：

   ```text
   把目前所有的修改（包括 screenshots 資料夾）commit 並推上 GitHub。
   ```

3. 到 e-Peer 寫今天的紀錄（見下方）。
4. 照 [下課前步驟](../01-install/README.md#每週上課與下課要做的事) 登出 GitHub 並重新開機。

## 📝 e-Peer 紀錄

1. **今天做了什麼？** 例如：修正了〔…〕、加了〔…〕功能，共存了〔幾〕個版本。
2. **遇到什麼問題？怎麼嘗試解決？** 特別記下：自己測試或審查 AI 發現了什麼 bug？AI 有沒有說錯？
3. **作品或 GitHub 連結**：貼上 repo 網址，有發布的話也貼上網站網址。

---

## 本單元學到的事

- **git** 記錄版本，**GitHub** 是放版本紀錄的網站；`gh` 管登入，`git` 管版本。
- **改一件事 → 自己確認 → commit**：每個版本都能回頭查看或還原。
- **AI 說「完成」不等於沒有 bug**：自己設計檢查項目，再請另一個 AI 審查；審查的意見也要自己驗證。
- 有 AI 功能的作品，**AI 產生的內容也要查證**。
