# 第五堂｜改造開源作品：接手別人的專案

第五堂，約 100 分鐘。**開源作品**是作者把程式公開、允許別人下載和修改的作品。這堂課選一個開源範例，請 AI 下載、解說、跑起來，再動手改造；也可以參考其中的功能，延伸你自己的作品。

**重點：接手別人的程式時，先讀懂、先規劃，再動手改；改完要確認原本的功能沒有壞掉，並註明來源。**

> **課前準備**：完成第四堂的 [功能改進與 GitHub](../03-github/README.md)。

> [!IMPORTANT]
> **第五堂開始**：電腦已經還原。選玩法 A 的同學，在「文件」裡新建一個空資料夾 `science-app`，用 **Open Folder** 打開；選玩法 B 的同學，直接看 [玩法 B 的做法](#玩法-b-的做法)。兩種都要照 [登入 GitHub](../01-install/README.md#登入-github每次上課都要做) 的步驟登入。

## 兩種玩法，選一種

| 玩法 | 做什麼 | 適合 |
| :--- | :--- | :--- |
| **A. 改造範例** | 照下面的步驟改造「傅立葉畫台灣」，發布成自己的網站 | 想做一個新作品、對數學動畫有興趣 |
| **B. 參考功能，延伸自己的作品** | 打開你自己的作品，把範例下載到旁邊參考，再把喜歡的功能或做法加進你的作品（見 [玩法 B 的做法](#玩法-b-的做法)） | 想繼續把自己的作品做完整 |

老師也可能提供其他開源範例，做法都一樣。

| | 第四堂：改進自己的作品 | 第五堂：改造開源作品 |
| :--- | :--- | :--- |
| 起點 | **你自己**在 AI Studio 做的作品 | **別人寫好的專案** |
| 怎麼請 AI 做 | 一次改一件事 | **先請 AI 解說、提出計畫**，確認後才動手 |
| 怎麼檢查 | 自己測試 ＋ 另一個 AI 審查 | 再加上**自動測試**（`npm test`） |
| 怎麼發布 | 請 AI 發布一次 | **推送就自動更新**（GitHub Actions） |

## 這個 App 在做什麼？

把台灣的海岸線，用許多**大小不同、轉速不同的圓**一個接一個串起來，最後一個圓的筆尖就會畫出台灣。圓越多，畫得越像：1 個圓只能畫出一個圓，512 個圓就幾乎和地圖一模一樣。

背後的數學叫做**傅立葉級數**：任何封閉的曲線，都可以拆成很多個旋轉的圓相加。所以不只台灣，**任何圖形都畫得出來**。

先到[線上版](https://gemini960114.github.io/taiwan-fourier/)看一次自動示範，再開始動手。

## 玩法 B 的做法

AI 只看得到你打開的資料夾，所以要**打開你自己的作品**，再把範例下載到作品裡的 `reference` 資料夾參考：

1. 在「文件」裡新建一個空資料夾 `my-app`，用 **Open Folder** 打開，照第四堂的 [Step 1](../03-github/README.md#step-1把作品找回來) 把你的作品 clone 回來、啟動。
2. 下載範例：

   ```text
   請把 https://github.com/gemini960114/taiwan-fourier 用 git clone 下載到這個資料夾裡的 reference 資料夾，
   並把 reference/ 加進 .gitignore，不要推上我的 GitHub。
   ```

3. 讀懂你想參考的功能：

   ```text
   reference 資料夾裡的作品，是怎麼做到〔你想參考的功能，例如：用旋轉的圓畫出圖形〕的？請用高中生聽得懂的方式說明。
   ```

4. 用下面 Step 4 的「先規劃，再動手」，把功能加進**你的作品**（不是 reference 裡的範例）。
5. 確認你的作品原本的功能都還正常，commit 並推上 GitHub。
6. 在你作品的 README 註明「部分功能參考自 gemini960114/taiwan-fourier」並附上連結。

做完後，跳到 [下課前](#下課前)。

## 玩法 A：改造範例

以下 Step 1～5 是玩法 A 的步驟。

## Step 1：下載專案（git clone）

在剛才打開的 `science-app` 資料夾，對 AI 說：

**Prompt 1：下載專案**

```text
請把 https://github.com/gemini960114/taiwan-fourier 用 git clone 下載到這個資料夾裡（直接放在目前資料夾，不要多一層）。
```

> [!NOTE]
> **git clone** 會把整個專案連同所有歷史版本下載下來。之後你改的是自己電腦上的副本，不會影響原作者的專案。

## Step 2：請 AI 解說，再跑起來

**Prompt 2：解說專案並啟動**

```text
請用高中生聽得懂的方式介紹這個專案：它在做什麼、每個檔案和資料夾的用途、
傅立葉怎麼用旋轉的圓畫出台灣。然後安裝需要的套件，啟動開發伺服器，告訴我網址。
```

打開網址，試試看：

- 切換「台灣本島」和各縣市。
- 把圓的數量從 1 慢慢調到 512，看看畫面和「誤差」數字怎麼變。
- 打開「設定」，切換深色配色。

> [!TIP]
> 看不懂的地方就直接問 AI，例如「`fourier.js` 裡的 `reconstruct` 在做什麼？」、「為什麼 1 個圓只能畫出圓形？」

## Step 3：認識自動測試

**Prompt 3：執行測試**

```text
請執行 npm test，用簡單的話告訴我這些測試在檢查什麼。
```

這個專案有 3 組**自動測試**，例如：檢查 22 個縣市的輪廓都是封閉的、**圓越多，誤差一定越小**。

等一下修改程式後，再跑一次 `npm test`：全部通過，代表原本的功能沒有被改壞。這就是工程師請 AI 改程式時保護自己的方法。

## Step 4：創意修改

從下面挑一個題目（也可以自己想）：

| 難度 | 題目 |
| :---: | :--- |
| ⭐ | 換一套自己設計的配色主題 |
| ⭐ | 加入新的內建圖形，例如愛心、星星（用數學式產生輪廓） |
| ⭐⭐ | **自己畫模式**：用滑鼠或手指畫一筆，放開後用旋轉的圓重畫出來 |
| ⭐⭐ | 畫出自己的名字或簽名 |
| ⭐⭐⭐ | 加一張即時圖表，顯示每個圓的大小和轉速 |
| ⭐⭐⭐ | 匯入一個 SVG 圖示，畫出它的輪廓 |

### 先規劃，再動手

改別人的程式時，**不要一開始就叫 AI 直接改**。先請它提出計畫：

**Prompt 4：提出計畫**

```text
我想〔你的題目，例如：加一個「自己畫」模式，用滑鼠畫一筆後，用旋轉的圓重畫出來〕。
請先不要改程式，告訴我你的計畫：要改哪些檔案、怎麼做、做完我可以怎麼檢查。
```

讀一下計畫：看得懂嗎？有沒有會影響原本功能的地方？有疑問就先問，確認後再說：

**Prompt 5：照計畫做**

```text
照這個計畫做。完成後執行 npm test，並告訴我怎麼在畫面上確認新功能。
```

### 檢查你的作品

- [ ] 新功能照你的想法運作嗎？
- [ ] **用科學原理檢查**：圓的數量設成 1 時，畫出來的是不是一個圓？圓越多，誤差數字是不是越小？
- [ ] 原本的功能還正常嗎？切換台灣本島、縣市、自動示範、深色配色都試一次。
- [ ] `npm test` 全部通過嗎？

有問題就告訴 AI 哪裡不對。改得不滿意想重來，可以說「把剛才的修改全部還原」，git 會記得原本的版本。

## Step 5：發布成自己的網站

這個專案已經設定好 **GitHub Actions**：每次把程式推上 GitHub，就會自動跑測試、建置，並更新網站。

**Prompt 6：發布**

```text
請把這個專案發布成我自己的網站：
先用 gh auth refresh -s workflow 加上 workflow 權限（需要我在瀏覽器確認的話，把代碼和網址給我），
再用 gh 建立我自己的 public repo，名稱 my-fourier，把程式推上去（不要推到原作者的 repo），
開啟 GitHub Pages、來源設為 GitHub Actions，等部署完成後給我網址。
```

> [!NOTE]
> - 為什麼要加 **workflow 權限**？這個專案含有自動部署的設定檔（`.github/workflows/`），GitHub 規定推送這類檔案需要額外授權；「登入 GitHub」的 Prompt 沒有包含這項權限。
> - 部署大約需要 1～2 分鐘。可以在 GitHub repo 的 **Actions** 分頁看到進度，綠色勾勾代表成功。
> - 之後每次修改並推送，網站都會**自動更新**，不用再請 AI 發布。
> - 若 Pages 設定失敗，到 repo 的 **Settings → Pages**，把 Source 選成 **GitHub Actions** 就可以了。

### 尊重原作者與資料來源

這是改作別人的作品，請保留出處：

**Prompt 7：註明出處**

```text
在 README 最上面註明「本專案改作自 gemini960114/taiwan-fourier」並附上連結，
保留原本的「圖資來源與範圍」段落，然後推上 GitHub。
```

台灣縣市圖資來自政府開放資料，授權條款要求**標示出處**；改作時一定要保留。

### 下課前

1. 截一張作品畫面：按 `Win + Shift + S` 框選畫面，點右下角跳出的通知，在剪取工具按「儲存」，存進作品資料夾裡的 `screenshots` 資料夾。第六堂會用到。
2. 把修改和截圖一起存起來（玩法 A 推送後，網站也會自動更新）：

   ```text
   把目前所有的修改（包括 screenshots 資料夾）commit 並推上 GitHub。
   ```

3. 到 e-Peer 寫今天的紀錄（見下方）。
4. 照 [下課前步驟](../01-install/README.md#每週上課與下課要做的事) 登出 GitHub 並重新開機。

### 📝 e-Peer 紀錄

1. **今天做了什麼？** 選了哪個範例、玩法 A 還是 B、改造或加入了什麼功能。
2. **遇到什麼問題？怎麼嘗試解決？** 例如：改完後 `npm test` 失敗，AI 怎麼找出原因。
3. **作品或 GitHub 連結**：貼上 repo 網址和網站網址，並寫下你參考的開源作品來源。

| 李薩如圖形 | 兩個方向的振動頻率比 |

```text
在這個資料夾建立 Vite 專案，做一個〔題目〕的互動動畫，
可以調整〔參數〕，畫面用 Canvas，介面用中文。完成後啟動開發伺服器，告訴我網址。
```

## 本單元學到的事

- **git clone** 下載別人的專案，先請 AI 解說，讀懂了再改。
- 改別人的程式時，**先請 AI 提出計畫**，確認後再動手。
- **自動測試**能確認原本的功能沒有被改壞；科學原理（例如圓越多誤差越小）也是很好的檢查方法。
- GitHub Actions 讓網站**推送就自動更新**。
- 改作別人的作品，要**保留原作者和資料來源**。
